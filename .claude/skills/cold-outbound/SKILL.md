# The Cold Outbound System — Read Me First

**A four-document operating system for producing high-converting cold outbound, consistently and reproducibly.**

This is the index. It tells you what each document owns, the order to read them, and how to run a campaign with the system. The system encodes the **why and the order** of cold outbound; it sits *on top of* the execution skills and defers all *how* to them.

> **The one idea the whole system enforces:**
> Relevance is the only currency, it is manufactured **upstream** before a word is written, and the **process — not the writer's talent — is the source of consistency.** Inconsistent output is a process problem, not a craft problem. These documents are the process.

When this skill is active and the task is cold outbound, **read `COLD-OUTBOUND-CONSTITUTION.md` first**, then open the other documents by task using the table below.

`1 → 2 → 3 → 4`. The Constitution gives you the causal model; the Module and Spec expand its highest-leverage layer downward; the Condensed Pre-Flight is the shortcut you've now earned the judgment to use.

**Day to day (open by task):** use the *"Open it when…"* column above. You will not re-read all four every time — you'll open the one the current decision lives in. The Constitution's appendices (Pre-Flight checklist, diagnostic table) are the parts you'll return to most.

## The operating loop (how to run a campaign)

```
NEW or UNCERTAIN campaign  ─────────────────────────────────────────────┐
  (new vertical / new offer / post-market-shift / anything you're guessing)
  → Constitution: run the FULL Pre-Flight (Article V)
  → building the list?      → List & Segmentation Module
  → building the data/join? → Fit × Timing Join Spec
                                                                          │
KNOWN-GROUND campaign  ──────────────────────────────────────────────────┤
  (proven vertical you know cold + calibrated offer)
  → Condensed Pre-Flight instead of the full one
                                                                          │
BEFORE SHIPPING (always)  ───────────────────────────────────────────────┤
  → Standing Council must be UNANIMOUS (Constitution, Article III)
                                                                          │
AFTER SHIPPING (always)  ─────────────────────────────────────────────────┘
  → Sharpening Loop: diagnose which metric moved, change ONE variable,
    capture the learning (Constitution, Article IX)
  → a stable metric drops → you're back to the FULL Pre-Flight
```

The gate that never moves: **no copy is written until Pre-Flight passes and the Council is unanimous.** Everything below the line in the Causal Hierarchy (framing, framework, length, and the actual words) only runs *after* the layers above it are settled.

## Operating directives (for whoever — or whatever — runs this)

1. **Read the Constitution first** on any cold-outbound task. It governs everything else here.
2. **Never write copy before Pre-Flight passes.** Full Pre-Flight when uncertain; Condensed only on proven ground. If in doubt which, you're uncertain — run the full one.
3. **Work the Causal Hierarchy top-down.** A defect at any layer cannot be fixed below it. Don't fix a segment problem with a copy tweak.
4. **Defer all execution to the skills.** This system decides *what must be true and in what order*; the named skills do the building, writing, sending, and enriching.
5. **Ship only on a unanimous Standing Council.** Five lenses: First-Principles, Contrarian, Expansionist, Outsider, Executor.
6. **Sharpen on signal, never the calendar.** One variable per iteration; capture the learning; a stable metric drop sends you back to full Pre-Flight.
7. **Anti-overkill is a rule, not a preference.** Segment until the message changes, then stop. Enrich until it changes a decision, then stop. The system runs on relevance, not volume.
